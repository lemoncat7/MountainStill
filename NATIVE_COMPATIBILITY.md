## B: old host with externally prepared installed update

New independent owned case directory, actual v19 creates actual old saves. After
it exits, copy those exact primary/backup bytes to snapshot-compat-* files. Put
the official pinned v20 gameplay PCK into updates/<sha>.pck and prepare a clearly
labelled EXTERNAL installed-state fixture:active.json, previous.json with empty
old record+true snapshot-file existence, booting.json with phase armed. Record
path is the literal user://updates/<sha>.pck, not an OS absolute path.

The original v19 binary launches twice. The application must itself validate and
mount the official PCK, report v20 gameplay, progress the startup transaction and
remove booting.json after healthy startup. Driver never writes launching/healthy
or deletes booting. After both exits verify active/previous, PCK and old snapshot
SHA unchanged, valid progressing saves and normal exit0. Second boot establishes
active persistence. The v19 protected bootstrap/Store/Service remains old; this is
not a v20 complete-host upgrade.

No claim about GitHub network Service download, release-channel selection,
