# 已知视觉问题：回旋扇拖尾的单个三角片

## 本次实录中的事实

连续原生新档在第五章「镜月泽」第二战出现一次 `Invalid polygon data, triangulation failed`。调用链为 `cultivation.gd:1398 _ink_trail` → `:1544 _draw_weapon_skill_fx` → `_draw_combat_fx`。它位于游戏时间 1145.367–1165.100 秒（19:05.367–19:25.100）之间。

日志没有记录该绘制调用的准确帧，因此不能指出哪一帧的哪一个小三角片缺失。对覆盖此区间的 22 秒诊断片抽查六帧，人物、扇、守灵、护元、伤害与后续倒地转换正常，没有发现整个人物或场景的形变。正式交付保留完整原生片段，没有删掉这段。

该次第五章战斗与搜寻随后正常结束，胜利累计至 15；经济、物品和进阶记录继续沿用原新档。本轮保留现有绘制代码以保持连续影片与交付源码一致，不宣称原生控制台零错误。最终计数、完整运行结果与存档核对见 [本版验证记录](PLAYER_JOURNEY-v1.3.8-QA.md)。

## 机制与影响边界

现有 `_ink_trail` 已将带状光效拆成独立三角形，并跳过叉积面积不大于 0.01 的片段，仍有一次小三角形没通过引擎的多边形三角化。近退化浮点几何是推断，尚未采到该三角形的具体顶点，不能把原因当作已复现结论。

Godot 4.6.3 的该错误分支在分配多边形绘制命令之前退出，宏本身打印后返回，既不抛出致命异常，也不执行崩溃陷阱。这支持将本次事件定位为一次绘制命令被拒绝；不等于对所有环境作绝不崩溃的承诺。[官方渲染源码](https://raw.githubusercontent.com/godotengine/godot/4.6.3-stable/servers/rendering/renderer_canvas_cull.cpp)、[官方错误宏](https://raw.githubusercontent.com/godotengine/godot/4.6.3-stable/core/error/error_macros.h)。

此函数只绘制效果，不写气血、伤害、资源、物品、章节、技能冷却或存档。日志与持续录像用于检查是否复发、刷屏或停滞；单次日志不足以量化亚帧耗时，也不能替代性能剖析。

## 可复查的入口与后续修复方向

1. 保留本次未固定随机种子的完整动作/遭遇账本和原生影片。在账本中定位 `moon_marsh:1:fight`，可查看该场真实培养、装备、真气和时间。新开一个随机存档不保证产生相同的近退化几何，这不是稳定最小复现。
2. 独立视觉修订中先捕获失败三角形顶点，加入平移后大坐标、近共线、反向和短弧的绘制压力测试。
3. 一个待验证的最小方案是对已经拆好的三点片段使用 `draw_primitive`，避免再走多边形耳切三角化。官方 API 明确支持三点三角形；仍须先验证颜色、透明度、细边和足够多的 native 渲染帧，再决定采用。[CanvasItem.draw_primitive](https://docs.godotengine.org/en/4.6/classes/class_canvasitem.html#class-canvasitem-method-draw-primitive)。
4. 该候选方案尚未写入本版，也没有把修改后的效果混入这份冻结源码实录。
