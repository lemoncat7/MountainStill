# 镜中试招：暂停查看出招缘由

本页描述一个小范围玩家反馈增量，不是正式版或目标平台验收声明。版本、构建、公开发布和完整回归由总验收记录另报。

## 已观察的问题与完整操作

在 v34 的明确合成状态中，节气战术、战气20/40、炽炎诀实耗18气时，战斗条显示「就绪」，真实选择仍为普攻。原因是节气还要求预留战气。「就绪」代表基本施放条件允许，不保证立即施放。既有战术、冷却、主动间穿插普攻等规则不因本功能而改变。

进入镜中试招后，先点「暂停试招」，再手动点「出招缘由」。纸页显示：

- 当前战术、战气和每个已装配主动/兵器技的实际施放成本。
- 正在执行的动作与「当前择招条件」分开显示；已经起手的动作不会重新选择。
- 兵器不合、战气上限不足、冷却、疗伤门槛、已有护盾、战气不足、穿插普攻、节气预留与轮转等候等当前原因。
- 悬停说明真实战术优先级及疗伤/护盾条件。不将当前条件解释为下一招预报、胜率或普遍强弱。

「返回交锋」回到同一场暂停试招；「继续试招」关闭纸页并继续同一场。空格继续也清理纸页。「结束试招」或原有 Esc 取消返回山居，不覆盖上次已完成的同敌记录。没有自动换装、开战、奖励或正式资源消耗。正式交锋没有这项入口。

## 实现边界

- `duel_timeline.gd` 只增加显式只读 `skill_decision_snapshot()`。实际 `_hero_action()`、provider 选择及整个 `combat_tactics.gd` 保持 v34 字节不变。
- 读取真实 `_skill_available`、`_skill_eligible` 和 `_skill_cost`，由既有 `Tactics.choose` 返回当前选择。节气预留原因也使用同一策略对单个合法候选核验，不另复制预留公式或声称数值门槛。
- 只在手动打开时取快照。纸页 build 格式化缓存文本；重绘不调用择招探针。没有把新解释或字符串分配加入正常战斗逐帧路径。
- 快照/显示缓存只有临时值，没有 Session、Duel、provider 或 Node 引用。会话 ID 与递增代次校验拒绝旧页面/旧试招的返回、继续、结束动作；离开或结束清除缓存。
- 没有新运行脚本依赖，不改导出列表、美术、字体、透明桌面、人物比例、存档 schema 4、Bootstrap ABI 1、更新交易、默认平衡或已获得反击收益。战斗条原有文字与语义保持不变。

Godot 4.6.3，隔离可写 HOME/XDG，以下最终日志退出0且未出现脚本错误：

- `test_practice_decision.gd`：3114检查、0失败。包括具体原因、精度边界、实耗折减、危急疗伤、昂贵技能、当前已起手动作；288组战术/血量/战气/普攻插入组合与真实 `_hero_action` 选择相同。四战术每种至多120步×0.1秒的有界对照中，重复只读探针与未观察对照的全部返回事件、双 RNG、生命、资源和战报逐步一致；不称为完整长期战斗性能测试。
- `test_practice_decision_ui.gd`：3150检查、0失败，5次同一 host 生命周期循环。实际控件打开/返回/继续/结束、空格/Esc、960×320/540几何及可读字号、缓存、重复操作、旧代次/旧会话、正式交锋/完成试招禁用、正式状态/三 RNG/磁盘存档不变及弱引用释放均覆盖。

- 受影响既有检查：practice controls 4307/0、host 40/0、session 232/0、loadout UI 3626/0、live-loadout guard 119/0、tactics 164/0、combat report 15/0、control contribution 4973/0、combat HUD readability 221/0。

首次 UI 自测虽然计数为3144/0，但测试在 Node 已释放后强行调用 `_qbutton` 捕获该 Node 的包装 lambda，产生 Godot freed-capture 错误；该日志保留为不合格测试运行。最终测试改为先在真实控件已脱树、尚待释放时调用其真实包装回调，并确认释放；释放后对原 session/代次调用准确的生产语义 handler，验证被拒绝，不再调用已销毁的 lambda。最终日志无此错误。
