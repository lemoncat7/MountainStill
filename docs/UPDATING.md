# 游戏内更新（v1.3.9-test.1 起）

旧 v1.3.8-test.1 不含启动器，因此需要最后一次手动安装新版完整包。此后点右上角“山”→“版本更新”。无需登录、令牌或管理员权限。

- 正式频道：排除草稿与任何预发布版本；测试频道：正式版和测试版一起按 SemVer 比较。不按发布日期排序、不自动降级。切换频道会取消请求并撤销尚未应用的下载选择。
- 自动检查只在游戏运行时进行：启动延迟 15 秒，此后每 6 小时一次。可以在面板关闭；关闭后不自动联网，游戏仍可完整离线游玩。失败/限流不会阻塞游戏，不频繁重试。手动“检查更新”不等于下载。
- 下载 → 校验 → 明确确认应用。关闭面板不强行中断下载，“取消下载”可停止。不会自动安装、强制升级或启动下载的 EXE。
- **内容热加载**仅支持严格 JSON 的短山居文案与墨色：修行进度墨线、丹房叶色与提示实时刷新；不重启、不换场景、不改存档。不是任意脚本热替换。
- **游戏 PCK 更新**：先保存并独立备份存档，再由原程序重启，在加载任何游戏脚本前挂载校验过的 PCK。引擎、原生扩展、启动器 ABI 或存档模式不兼容的更新被拒绝，需完整安装包。
- 更新保存在 Godot 的 `user://updates`，不修改 Windows EXE 或 macOS `.app`，不触碰签名包内资源。原有 `cultivation_save.json` 路径不变。

## 恢复

首次启动更新未完成明确的游戏就绪确认，下次启动会恢复上一版及更新前快照。该快照独立于游戏轮换的 `.bak`，不会被日常自动保存覆盖。新版本存档另存留档，不做跨版本合并。手动“回退”会提示其恢复更新前进度的代价。失败界面停止游戏处理，确认后重启恢复。高级恢复参数：`-- --safe-mode`。磁盘/权限故障会停止恢复而不是默默新建存档。

## 发布者流程

使用 Godot **4.6.3 standard** 与该版本正式导出模板，运行 `tools/build_updater_release.sh`。输出 Windows/macOS 完整包、两个平台 PCK、`MountainStill-update.json`。脚本只本地构建，**不发布**。游戏版本/导出版本/清单版本需一致；Windows 的数值版本不能含 prerelease，因此 UI 与清单保留完整 SemVer。

将同一轮构建的清单与其指定的 PCK 作为同一 GitHub Release 的附件发布；release tag 必须等于 `v` + 清单版本。测试版同时设置 GitHub prerelease 标记。不要重写旧附件。首次用户拿完整包，已有启动器用户拿 PCK。

清单：`schema:1, engine:"4.6.3", bootstrap:1, save_schema:4, version, packages:{windows:{kind,asset,size,sha256,restart_required},macos:{...}}`。PCK 类型 `kind:"pck"`，`restart_required:true`。下载 SHA-256 与 GitHub 若提供的 asset digest 一致，并检查实际大小。清单最高 64KiB，PCK 最高 512MiB。最多检查 1000 条 release；超出则报告未完整检查而非宣称最新。

构建采用文本脚本/场景，PCK 排除启动器、`scripts/update_*`、project 配置、全局类缓存与 UID 缓存。运行时再次验证 PCK v3 全部目录边界、重叠、路径、保留命名空间，不解压 ZIP、不允许原生代码/加密/移除/增量条目。**固定 ABI 下不能依赖新增全局 class_name 注册表、自动加载项或工程设置；这类变化需完整安装包。** 普通新增脚本可通过明确路径加载。

内容专用 release：创建 `MountainStill-content.json`，内容严格为 `{"schema":1,"accent":"#9e4739","message":"山色常新，修行如初。"}`，再运行 `python3 tools/write_update_manifest.py <目录> --version <新版号> --content`。文案最多 120 字符，禁控制字符；16KiB 上限。发布清单和 JSON，无代码。内容版本独立显示/存储，不伪称游戏脚本版本已升级；后续脚本 release 必须使用更高版本号。

## 信任与限制

仅固定 `lemoncat7/MountainStill` 的 GitHub HTTPS release 及受限 GitHub asset CDN 跳转；无任意 URL/令牌输入。SHA-256 防止损坏与不匹配，**不等于独立发布者签名**：信任边界仍是 GitHub TLS 和该仓库发布权限。PCK 中的游戏脚本可执行代码；命名空间检查不是沙箱，不能防御已被攻陷的发布者。没有自行生成/冒充签名密钥。

构建机为 Linux。Windows/macOS 产物可做结构与载荷验证，但不能替代 Windows/macOS 原生重启、磁盘故障、权限/Gatekeeper/SmartScreen、签名与完整图形体验验收。程序原本未做 Developer ID 公证；更新机制不改变这一点。

### 并发保护

启动器持有本机回环地址 `127.0.0.1:47893` 的独占监听锁，不接受远程连接、不读写网络会话数据。第二个实例在接触存档/更新前停止。进程退出或崩溃后由系统释放，无 PID 重用/残留锁文件问题。若该端口被其他程序占用或本地网络策略禁止监听，程序安全拒绝启动并提示，不自动重启循环；关闭重复实例/排除端口冲突后重试。原生平台的权限/重启时序仍需实机验证。

### 已有代理环境

可沿用启动游戏进程时已有的 `HTTPS_PROXY` / `HTTP_PROXY`（或小写同名）环境变量，格式为无认证的 `http://主机:端口`，通过 Godot 的 HTTP/HTTPS CONNECT 代理接口连接；默认端口 80。不会改操作系统网络设置、记录代理值、保存密码或关闭 TLS 验证。暂不支持代理 URL 内嵌账号密码、SOCKS、HTTPS 代理协议或系统 PAC 自动探测；不符合格式时使用默认直连。此设置不改变固定 GitHub 目标及 CDN 跳转校验。
